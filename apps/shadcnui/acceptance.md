# Acceptance

- [ ] Clicking the switch toggles it, and each toggle writes the machine's target state into the demo row — two clicks, one row, back where it started. {#accept-switch-toggles}
- [ ] Before anything is clicked the switch reads its initial state from the machine alone: no data-empty-row on the control, aria-checked bound "false", and the first write keyed by the filter's pinned id. {#accept-initial-synthesized}
- [ ] The row readout beside the control shows the same field the control binds, and the two can never disagree because they are one row. {#accept-state-is-a-row}
- [ ] No screen hands a DOM event to app code: none carries a data-on-* binding or a script, and every module any route lists is named by a chart on that screen, so behaviour is data even where a value is computed. {#accept-zero-js}
- [ ] The machine JSON shown on the screen is the machine in the markup, and it is valid XState config the published #Machine subset vets. {#accept-machine-visualizable}
- [ ] Clicking a tab trigger activates its panel and writes the active tab plus every trigger's aria-selected as one row — the component-generated click@trigger arrows, both directions. {#accept-tabs-activate}
- [ ] Clicking a picker option writes the choice, its readout label and every option's aria-selected as one row; the listbox is a popover the trigger commands, so open/close ships as attributes the platform performs. {#accept-picker-select}
- [ ] Every screen reads correctly in both appearances from one token declaration — the storyboard's -dark frames are the light frames' twins, with no .dark fork. {#accept-dual-appearance}
- [ ] The catalog links every live component and says plainly which are next, specified, or later — no entry renders a control that does nothing. {#accept-catalog-links}
- [ ] The catalog is the app's only index: it is the one route on the strip, so the terminal draws no strip at all, and every other screen carries its own one-link way back — a width the route's depth decides, not the roster's size. {#accept-way-back}

- [ ] The dropdown menu's caret walks all six items with Up and Down whatever kind each is, Home and End name its ends, Right moves nothing, and typing a letter jumps to the item it names while the letters accumulate in a buffer that clears a second after the last keystroke; no item is stamped with a tabindex, because every one keeps its own tab stop. {#accept-menu-walk}
