omnishell/ui — intermediate representation

Compiled from brief.md against the prelude and the published platform doctrine — the terminal's capability roster (plugins/omnishell/terminal.cue), its machine vocabulary (plugins/omnishell/machine.cue), and the design ground in plugins/pronto/docs/2026-08-30-machines-not-widgets.md. The app is a gallery that is also a proving ground: each component ships as a CUE definition whose tag expands into the binding vocabulary, whose behavior is a #Machine, and whose acceptance suite is the gallery screen that demos it. This first cut carries the catalog and the switch; the tabs screen is the named next step (decision-08 holds the combobox last).

State

One entity, and it is tab-tier by design: a gallery's state is the visit's (decision-01). No pipeline — a tab entity has no table to publish. No escape hatch of any kind: the whole point of the app is that the components need none.

Handlers

Every one of them is decision-34 in practice: a chart names a leaf where it cannot compute the value it needs, and nowhere else. What survives unqualified is the part that mattered: no screen carries a data-on-* binding or a <script>, so no DOM event is ever handed to app code, and a module reachable any other way is refused.

starts-with — whether the letters typed name this item

Typeahead's whole decision, as one boolean per item: the chart draws an arrow to every destination and asks each in turn, so the item the prefix reaches is the one that answers and the inventory stays in the chart rather than in a module that would pick one.

Its params carry two facts about the arrow. label is what the module matches; keys is the keystrokes that REACH it — the shortest prefix of that label no earlier item's label carries, since first-guard-wins gives a shared one to the earlier arrow. One character for most of them, two where two labels start alike, and a walk can guess neither: an event satisfying a guard over accumulated text is not derivable from a module's name, and the letter that disambiguates belongs to no arrow of its own. keys is the plural of the event field key — one keystroke per character, delivered in order — which is what lets a chart-derived walk drive an arrow no single event can select.

is-printable — whether a keydown is a reader typing

A single character is typing; Tab, Escape, Enter, Home, End and the arrows are all longer, and every one of them is somewhere else's arrow. It guards the arrow that extends the buffer without moving the caret — a reader mid-word whose letters name nothing yet — and that arrow targets its own state, which is what re-arms the timer on every keystroke rather than only the first.

type-into — the buffer with this keystroke on the end

An assign holds a literal or a leaf, and buffer plus key is neither a literal nor anything the chart can spell, so the arrow stays in the chart and the string it writes comes from here. It is the fold seat's shape in one line: the previous value and the event, and nothing else in scope.

has-prefix — whether the buffer holds anything

The timer that clears the buffer arms on every state entry, so without this it would write an empty buffer over an empty one once a second per move — and a write that changes nothing still wakes the store and re-renders everything reading the row. The timer is TARGETLESS for a second reason: one whose transition re-enters the state it fired in re-arms itself, and the screen never settles.

is-key — which key a keydown carried

A #Machine's guard is a module or nothing: the transition grammar has no literal comparison, and every arrow that moves a roving tabstop differs from its siblings only in the key that selects it. So one module reads event.key against a key carried as a param, and serves every arrow #OneOf draws for every group on the page.

It reads the EVENT and never a row, which is the leaf rule (decision-34) holding: a transition stays decidable from the row and the event, and the chart stays the whole inventory of what can happen. The params are literals, which is what lets the chart-derived walk synthesize the very event each arrow answers to instead of guessing at a keyboard.

is-code — whether what has been typed is a complete code

A length and a character class, neither of which a transition grammar has: there is no comparison in it, and a chart that could state one would be a chart with an expression language in it. So the predicate is a leaf and the number is its param — the same number the control's maxlength, the column's constraint and the stylesheet's track count are emitted from, so the boxes a reader sees and the length that admits them cannot drift (decision-44).

is-digits — whether what has been typed could still become one

The arrow it guards is the one a reader is on for five keystrokes out of six, and the arrow BELOW it is the one that calls a keystroke wrong. Having both is the claim: a code half typed is not an invalid code, and only a character that can never be part of one is.

has-nondigit — whether a character no code can hold has been typed

The exact negation of the one above, and having both is the claim: the two partition every string between them, so the three arrows on one event are exhaustive without a candidate that catches whatever the others declined. Decisions

Every entity is tab: a gallery's state is the visit's, so nothing here emits a table, a policy, a publication or a pipeline; the durability ladder is demonstrated by the rows dying with the tab, not documented.

Behavior is data, not code: each stateful component carries a #Machine — the XState-JSON subset whose one action is writing the target state into the row's field — executed by the terminal through the same path as a Jessie reduce, so replay, tempo and the refusal event apply with the machine knowing nothing; a guard is the cliff where an app writes the reduce instead, and this gallery crosses it once, for a value and never for a decision (decision-34).

State names are the ARIA attribute's values: the switch's states are 'true' and 'false' because aria-checked speaks that vocabulary, so one field binds the semantics and the styling hook and no component carries two spellings of one fact.

Components are CUE definitions composed into #Screen.markup at emit; the omnishell-- tag survives in the served HTML as an inert wrapper — visible to devtools, CSS and the visual battery, registered with nothing, no customElements.define and no shadow DOM.

shadcn's theming is CSS variables, so its palette lands on the design-token contract and dark mode is each token's light-dark() twin; there is no theme-switch control because appearance is a token resolution, reviewed as the storyboard's -dark frames.

No auth block: a component gallery gates nobody, and a sign-in in front of a reference is a toll.

The machine is the writer of the initial fact: the switch region carries no data-empty-row and the terminal synthesizes its fallback row from the filter's pinned id plus the machine's initial; the row-readout pane keeps a data-empty-row because it shows a fuller row than the machine's one field, and the generate-time agreement check keeps the two declarations one fact.

The combobox is deliberately last in the catalog: its virtual-focus behavior is the one part with no declarative precedent, and it is where the widget tier died the first time.

N triggers share one machine, so the discrimination is component-generated: #Tabs writes one click@trigger-<name> transition per (state, trigger) pair — a grammar the interpreter resolves and no author learns — and each transition's literal assigns keep one aria-selected column per trigger in step, so the ARIA contract stays plain bindings over the row.

The picker splits its two behaviors across the two closed vocabularies that own them: selection is a machine — one state per option, component-generated click@trigger arrows, literal assigns keeping the readout label and every aria-selected in step — and openness is the platform's popover commanded by commandfor, with anchor positioning in CSS. Light dismiss, top layer and the invoker's expanded state ship as two attributes and zero script. An option button carries both at once: its id feeds the machine, its command closes the list.

The segmented control is a radiogroup, not a bag of pressed buttons. shadcn's ToggleGroup offers both spellings, and the single-select arm is the one a #Machine already fits: the field holds exactly one state name, so the choice is single-valued, and every arrow's literal assigns project that one value onto all N chk_ columns at once — which is what leaves no arrow able to check two members, or none. That is the promise role="radiogroup" with aria-checked makes and role="group" with aria-pressed does not. The self-arrow is omitted as #Tabs omits it, so there is no deselect and a click on the checked option finds no candidate and writes nothing. The derived columns are chk_* because the attribute is aria-checked — an ARIA column's prefix names the attribute it binds, which is decision-03 extended one notch for the case where N triggers share one field and the field cannot itself be the ARIA value. The keyboard is APG's radio group in full: the tabstop is the chosen option's, so data-rove binds the very column aria-checked binds and one write moves the selection, the tab order and the reader's focus together — they cannot disagree because there is nothing to disagree with. The arrows come with it and never without it: a tabstop with no arrows to move it strands every unchecked option outside the tab order, which is why #OneOf draws both under one flag rather than letting a skin take half. Right and Down go to the next option, Left and Up to the previous, both WRAPPING as the pattern asks — a compile-time chart can state a wrap the read tier's lane clauses decline, because there the pattern is not known. Home and End name the ends, and the one that names the state it leaves draws no arrow, which is the rule the clicks already keep. Ids are tg-<key>-item-<name>, and neither key nor option name admits a hyphen, so the separator is unreachable from either side and two groups on one screen cannot collide; the id sits on the button and on nothing inside it, because from resolves to the nearest ancestor carrying one.

A machine's arity is one row; multiplicity is the region's. The accordion ships both of shadcn's arms from one definition to prove it rather than assert it: type="single" is one region over one row whose states are the item names plus a closed none, with one exp_ column per trigger moved by literal assigns and a self-arrow targeting none — the tabs shape plus the arrow a tablist must not have. type="multiple" is N sibling singleton regions on one collection, each pinning id=eq.<item>, each carrying the switch's two-state machine with its field renamed and its event narrowed: no context and no derived column, because the field IS aria-expanded's value. Nothing was added to the vocabulary for the second case, which is why #Machine never needed a plural — the arity lives in the entity's shape (one row of 1+N columns, or N rows of two, the item set moving from the field's constraint to the pk's) and in how many regions the expansion writes. And because there is no group row at arity N, only the single arm binds data-state: which item is open is the group's own fact, and no trigger's aria-expanded spells it. The keyboard is APG's required contract whole and nothing past it, at both arities: Tab walks the triggers in document order and an open panel's content after them, and Space or Enter opens the focused header, both of them native button behaviour. Up and Down between headers, and Home and End, are a second chart beside the expansion's — #OneOf walking the headers over caret and cur_*, vertical only, because a header list gives a reader no reason to press Left or Right. It has to be a second chart: both narrow their arrows to the same headers, and which header is open and which one the reader stands on are two facts one field cannot hold without becoming their product. No tabindex ships with them, and that is the pattern's contract rather than a deferral: APG keeps every header in the Tab sequence, so the caret is data-focus and a roving tabstop would take two of three headers out of a sequence the standard puts them in. Ctrl+PageUp and Ctrl+PageDown stay absent — the walk's key set is APG's own for moving through a list, and a chord is not in it.

Every accordion arrow is narrowed to click@acc-<key>-trigger-<item>, the multiple arm's included even though its region holds exactly one button: from resolves to the nearest ancestor carrying an id and the bare event type is the candidate list's fallback, so an unnarrowed click would fire from the panel a reader is clicking inside and collapse it. A bare click is safe only where the region IS the affordance, which is true of the switch and of nothing else in this catalog. The panel's collapse is then CSS keyed on the trigger's own aria-expanded, not a bound hidden: a bound boolean attribute is absent when its value interpolates empty, so binding it would need a column holding the empty string — a second spelling of what aria-expanded already says. One rule serves both arms, and a fourth item costs no stylesheet.

Dialog and tooltip earn no machine and no row. Openness, the top layer, the inert background that is also the focus trap, Esc as a close request, the focus return and the placement are all the platform's — commanded by commandfor, positioned by anchor-name — so the tier-0 claim lands as a counted absence on the screen rather than a sentence about it, and the two panes every other screen fills with a row and a chart name who holds each state instead. Modal and non-modal are one definition's two parameters because neither contains the other: modal buys the inert background and loses backdrop light dismiss, non-modal buys light dismiss and loses the inert background, and closedby, which would close that gap, is outside this tree's measured engine matrix, so nothing depends on it. What the tooltip ships is APG's disclosure, not APG's tooltip: interestfor is implemented in no engine, so a hover-opened surface cannot ship without script, and the click-opened popover — complete, correct, zero script — ships under the name tip carrying no role="tooltip" and no aria-describedby rather than wearing a contract it does not meet. The CSS-only hover surface that would wear that contract fails WCAG 2.1 SC 1.4.13's Dismissable clause by construction, because CSS has no Esc, so the gallery prints the clause rather than rendering the failure for someone to copy.

Badge, card and alert are one catalog entry because they are one family — the family with no behavior — and what they contribute is not a machine but the demonstration that shadcn's variant vocabulary lands on the token contract with no new token name. The two standard panes hold that instead: The row becomes the checked claim that the screen mounts no region and no machine, and The machine becomes The tokens, the variant→token map printed as data, because for a component whose whole content is presentation that map is the machine — and each row carries the selector chain it describes, so the suite folds the screen's stylesheet through the table and refuses a cell the rules do not set, a declaration no cell lists, or a variant on the screen with no row. It names tokens and never values — a hex printed on the screen would be the palette's second declaration, which is the fork decision-05 exists to prevent. Two divergences from shadcn are deliberate: the card title ships as a real heading, since a card grid of divs leaves the document with no outline, and it names the <article> it heads, a boundary a screen reader announces on entry, rather than leaving that boundary unnamed or promising the landmark role="region" would; and role="alert", which shadcn hard-codes on every variant, is treated as the assertive live region it is — it interrupts, so it is correct only for content that appears after load and is urgent. #Alert therefore takes a live setting defaulting to none, and the gallery ships one specimen of each of the three answers. The corollary, written beside them because it is the one that bites: a POLITE region must be mounted before its content changes, or the only change it reports is its own arrival and nothing is spoken; role="alert" is the exception, announced when the element is inserted with its text already in it. The terminal injects a screen whole on navigation, so the assertive specimen speaks on every arrival at /primitives — printed on the screen, because a gallery that demonstrates a role owes the reader its cost.

The combobox ships the filtering the platform owns and nothing past it: <input list> plus <datalist>, which the UA maps to role="combobox" with autocomplete="list" and haspopup="listbox", and a form holding no button, which submits on change — so a picked suggestion writes the row with zero script. The UA runs the popup's lifecycle and exposes no expanded state for it, so APG's required aria-expanded is one more thing neither the page nor a reader can see, printed on the screen beside the pair's other costs. The option list is stated once and emitted three times, as the datalist, the input's pattern and the column's CEL, so a control-side gate and a store-side constraint that could drift are one declaration; the pattern is load-bearing rather than decoration, because change also fires on blur after partial typing. This screen's write is a form's rather than a machine's, because a pick is a commit on a gesture (decision-17).

One wall stands between that control and shadcn's cmdk combobox, and the screen names it rather than faking past it. Virtual focus: moving the active option is a read of the row after this one in a foreign, live-filtered collection, which row closure forbids, and neither the machine vocabulary nor the data attributes names an ordinal — what decision-08's "no declarative precedent" was pointing at, and the only thing it was pointing at. The two halves that are not walls are the two /command runs: an assign reading the event's value (decision-24), and a nested region whose interpolated filter tracks the enclosing row. This screen still declines the machine, and the reason is the column rather than the vocabulary: ComboboxDemo's choice enumerates five values, a per-keystroke assign would state values it does not admit, and a chart holds no pattern to refuse them while the control holds one and fires it on submit. A pick is a COMMIT, not screen state as it changes. So the two screens are the two answers — literals the UA filters, against data a column filters — and neither supersedes the other.

The switch's two-state machine is not a switch: it is the shape of every binary control, so checkbox, toggle and collapsible are one generator whose only parameter that matters is the ARIA attribute the field spells — aria-checked, aria-pressed, aria-expanded — which is decision-03 at its conclusion, and the screen prints the five-row table that makes the claim checkable rather than asserting it. Its fifth row is the switch, and it carries the one difference: the switch's region IS its affordance and carries no id, so its arrows keep the bare click where the four generated here are narrowed to a trigger — the suite erases the field, the trigger and that narrowing, and holds all five to one chart. The generator takes next, a map from state to what the trigger's click makes true next, so the key set IS the state set and a state no value names has no incoming arrow — which is exactly what the checkbox's third state needs: aria-checked speaks mixed, so the tri-state arm has three states and the cycle is APG's, a partially checked select-all checks everything and from there the control is the two-cycle, with nothing returning to mixed, because partial is a fact about the items and a machine is closed over its own row. One field cannot hold that function, and the two things that could are a machine whose states are the item subsets — decision-11's derived-ARIA-column extension, at 2^N states — and a cross-row read row closure forbids. Neither is paid: the select-all is a component of its own, whose value is a column rather than a field (decision-47), so this generator's tri-state arm is gone and what is left here is the binary shape it always was. Every arrow is narrowed to its trigger's id including the toggle's, whose region IS the affordance as the switch's is, because the id costs one attribute and the narrowing then survives a caller who wraps the button in something clickable. The collapsible is the accordion's multiple arm with one item and is described as exactly that — same trigger, same panel hidden by a rule keyed on the trigger's own aria-expanded, same two-state machine — dropping only the item set and the group wrapper. And alone in this catalog the screen defers no keyboard at all: a checkbox, a toggle button and a disclosure are all buttons, and Space and Enter press a button, so APG's required contract for all three is complete with no tabindex and no key handling; the roving-tabstop deferral belongs to the patterns that group N affordances under one label, and none of these three does.

The radio group and the segmented control are one machine under two skins, and the gallery ships the second entry by factoring rather than copying. #OneOf is the single-select chart — one state per option, one derived ARIA column per option, one arrow per (state, other option) pair whose literal assigns write the whole derived set as one row, and no arrow from a state to itself — and #ToggleGroup, #RadioGroup and #Tabs are three markups over it, so a fourth single-select entry costs a skin and no chart. What makes a radio group a radio group is therefore entirely outside the machine, and it is three things, all markup: a legend that is on the screen and names the group through aria-labelledby, where a segmented control hides its name in an aria-label; a description per option, carried by aria-describedby as a sibling the button points at — nested it would fold into the option's accessible name, since a button is named from its content, and its own id is what makes a click on it resolve to no arrow (decision-13's narrowing, load-bearing again); and one option per line, because a description per option is what a compact control has no room for. The group emits no name and no hidden input: it is the shape a form submits, but it is in no form and the write is the machine's one stated row, so the screen says so rather than dressing a control as a submit that cannot happen. The keyboard is exactly the segmented control's (decision-11), because it is the same chart: #OneOf takes a rove flag and the skins that are composite widgets set it, so the tabstop and the arrows arrive together or not at all — and with them focusin, so a Tab into the group leaves the column naming whatever the reader is standing on rather than something to reconcile later. The tablist takes the same flag and the same arrows, so the three composite single-select skins in this catalog rove and none of them spells a keyboard of its own. There is no aria-orientation, and now for the opposite reason — both axes move the tabstop, so there is no axis to tell a reader about. The menu's menuitemradio set is the same generator with the flag off (decision-29): a menu's arrows cross every item, not the radio subset, and half a keyboard there would be the failure this pattern avoids. The sharing is a checked fact rather than a claim: the suite canonicalizes both emitted charts by option index — guard included, since a copied generator drifts in the key as easily as in the target — and refuses them if they differ. That holds the two CHARTS to one, not the two generators — a copy that drifted would fail and a verbatim one would pass — so the factoring is what keeps there from being a second generator, and the check is what keeps one from mattering unnoticed.

Relative movement needs no vocabulary. A machine has no arithmetic and none is missing, because from each position the component draws the ABSOLUTE arrow the step lands on: from page three, Next is the arrow to page four, filed under the step button's id instead of that page's. The two components wrap that one machine in their own markup, and what separates them is the ARIA contract and whether anything is projected. The page list is a <nav> of buttons because a page here is a column of a row and not a location, so shadcn's <a> would be a link to nowhere wearing a link's role. Two static attributes, and nothing in the chart. aria-current is decision-03 on a token attribute rather than a boolean one, so the column holds the attribute's own value — page for the page list, true for the dots — and the entity's constraint prints that vocabulary rather than a boolean someone translates.
